# Property Finder — кейс модернизации Ruby on Rails

**Формат:** инженерный портфолио-проект, модернизация существующего приложения, не разработка недвижимости «с нуля» и не подтверждённый коммерческий проект.

**Статус на 02.11.2026:** основная публичная и агентская функциональность проверена локально; полноценного production-деплоя нет, покупка домена и подключение SMTP отложены.

## Задача

Исходное Rails-приложение содержало устаревшую инфраструктуру сборки и непоследовательный пользовательский опыт. Цель модернизации — сохранить полезную структуру проекта, привести публичные страницы и кабинет агента к единой визуальной системе и довести основные пользовательские сценарии до сохранения реальных данных в PostgreSQL.

## Что выполнено

- Переход на Ruby **3.4.12**, Rails **8.1.4**, Devise **5.0.4**, Node **22**, esbuild вместо Webpacker.
- Главная страница, каталог объектов с поиском/фильтрами/сортировкой/пагинацией, карточки объектов и профиль агента.
- Кабинет агента: управление объявлениями, статусы, показатели из реальной БД, входящие обращения с изменением состояния.
- Два подтверждённых сценария связи: обращение по объекту (`Enquiry`) и сообщение непосредственно агенту (`AgentMessage`). Оба сохраняются в БД до отправки email, уведомление — best effort.
- Блог из шести образовательных DEMO-статей в изолированной тестовой среде; админское управление, публичные статьи, иллюстрации.
- Оригинальные SVG-иллюстрации, честно подписанные как графика, **не реальные фотографии недвижимости**.
- Безопасность: авторизация владельца объектов, приватный inbox, закрытые статьи, ограничения форм по IP/email, обработка ошибок, проверка загрузок, защита пустых flash-уведомлений и приватные метаданные.
- Производственная упаковка: Dockerfile, healthcheck, проверка конфигурации запуска и план отдельного PostgreSQL/медиа-хранилища.

## Архитектура пользовательского сценария

**Гость → каталог → карточка объекта → форма Enquiry → валидация → запись в PostgreSQL → уведомление best-effort → приватный inbox владельца → статус Contacted/Closed.**

Аналогичный сценарий предусмотрен для прямого обращения из публичного профиля агента через `AgentMessage`. Письмо не является единственным источником информации: сообщение сохраняется в базе до попытки отправки.

## Что не заявляем

- Никаких реальных сделок, арендаторов, выручки, коммерческой конверсии или подтверждённых адресов недвижимости.
- Шесть статей и двенадцать объектов — **учебный контент**, а не данные реального риелторского бизнеса.
- Существующие SVG не являются фотоснимками объектов.
- Нет подтверждённой production-доставки email, постоянства файлов после Railway redeploy, проверенного restore-бэкапа и работающего публичного деплоя.
- Google Maps не активирован: для вымышленных адресов ставить реальные маркеры было бы некорректно.
